# План интеграции Gemini TTS через OpenRouter

> Статус: реализовано 2026-09-28 на ветке `feat/gemini-openrouter`, транспорт —
> OpenRouter (без стриминга, см. §2.1). Отличия от плана — в §10.
> Модель: `google/gemini-3.8-flash-lite-tts` через OpenAI-совместимый
> `POST https://openrouter.ai/api/v1/audio/speech`.
> Главная идея: Gemini отдаёт сырой PCM, поэтому звук готовим своим
> обработчиком на Python, без ffmpeg.

---

## 1. Что уже известно (замеры 2026-09-28)

| Факт | Значение | Откуда |
|---|---|---|
| Выход модели | PCM s16le, 24 кГц, моно | прямой Gemini API (`audio/l16; rate=24000`) |
| TTFA напрямую у Google, тёплое соединение | ~0.9 с (0.65–1.0) | 10 запросов, из контейнера бота и с Windows |
| TTFA Fish, для сравнения | 0.63 с (API); 0.77 / 1.13 / 1.88 с p10 / p50 / p90 от сообщения до звука | контейнер + 238 строк лога |
| ffmpeg на сыром PCM (флаги бота) | +0.73 с до первого кадра: копит вход | контейнер, 15 прогонов |
| ffmpeg с `-probesize 32 -analyzeduration 0 -fflags nobuffer` | +0.13 с | то же |
| Пересчёт на Python | < 1 мс на чанк | `audioop` (в Python 3.13 его нет) |
| Средняя длина текста для провайдера (bussshy) | 14.1 симв., медиана 12, p99 47 | `scripts/usage_stats.py` + Discord, 30 дней |
| Объём bussshy | ~15 600 симв./мес | `exports/bussshy-usage-30d-2026-09-28.md` |
| Зависимости образа | `numpy` 2.4 есть (из piper-tts), `soxr` нет (колесо 245 КБ) | `pip` в контейнере |

Что известно про OpenRouter из документации:

- **Параметры запроса:** `model`, `input`, `voice` (27 голосов Gemini: Kore, Puck, Zephyr, Charon…), `response_format`: `pcm` (по умолчанию) или `mp3`.
- **Ответ** — сырые байты. Частота и число каналов указаны в `Content-Type`, например `audio/pcm; rate=24000; channels=1`.
- **Ошибки** приходят в JSON. Gemini тарифицируется по токенам: входной текст плюс выходное аудио.

**Не проверено, выясняется на этапе 0:**

1. Отдаёт ли OpenRouter PCM потоком по мере генерации или ждёт готовый клип.
2. Сколько добавляет лишний переход через OpenRouter к TTFA.
3. Какие частота и разрядность реально приходят и бывают ли чанки нечётной длины.
4. Поддерживаются ли `speed` и `instructions` (стиль речи).
5. Коды и формат ошибок: 401, 402 (кончились кредиты), 429, 5xx; есть ли `Retry-After`.
6. Цена в OpenRouter за типичное сообщение.

## 2. Этап 0: проба API (блокирует остальное)

Нужен ключ OpenRouter с кредитами. Скрипт `scripts/probe_openrouter_tts.py`: он остаётся в репо как инструмент диагностики. Запускается в контейнере бота, чтобы идти через ту же сеть (gluetun), и замеряет:

- **Время до первого байта и до конца ответа** на короткой (12 симв.), средней (~40) и длинной (~150) фразе, по 5 раз, на тёплом `httpx.AsyncClient`. Если первый байт приходит почти одновременно с концом на длинной фразе, значит, OpenRouter буферизует.
- **Формат потока:** заголовки, размеры чанков, чётность длины каждого чанка.
- **Параметры:** работают ли `speed` и `instructions` (сравнить длительность и звучание).
- **Ошибки:** неверный ключ → 401; 429 при серии запросов, если получится без злоупотребления; тело и заголовки ошибок.
- **Сохранение образцов** (WAV), чтобы прослушать русскую речь нескольких голосов.

**Точка решения:**

- **OpenRouter стримит, TTFA ≤ ~1.2 с:** идём по плану.
- **OpenRouter буферизует:** для коротких сообщений (медиана 12 симв.) генерация целиком тоже занимает ~1–1.5 с, поэтому оценить, приемлемо ли это. Альтернатива — транспорт напрямую в Gemini API (`:streamGenerateContent?alt=sse`). Обработчик PCM и всё остальное из этого плана не меняются, отличается только `stream_audio()`. Поэтому транспорт держим за маленьким интерфейсом (§3.2).

### 2.1 Итоги этапа 0 (2026-09-28, из контейнера бота)

`scripts/probe_openrouter_tts.py` плюс ручные проверки вариантов стриминга:

- **Стриминга нет.** Заголовки ответа приходят только когда весь клип
  сгенерирован, а байты аудио сразу следом за 0.04–0.3 с. Проверено:
  - запрос по умолчанию;
  - `stream: true`;
  - `stream_format: "sse"` и `"audio"`: параметры игнорируются, приходит сырой PCM;
  - HTTP/1.1 и HTTP/2.

  `/chat/completions` для модели закрыт («is a text-to-speech model and cannot
  be used with the chat/completions endpoint»). Единственный провайдер —
  Google AI Studio, `supported_parameters: []`.
- **Задержка до звука (тёплое соединение, медианы):**
  - 12 симв. — 1.55 с;
  - ~60 симв. — 2.07 с;
  - ~150 симв. — 3.9 с.

  Напрямую у Google со стримингом ~0.9 с при любой длине.
- **Формат:** `audio/pcm;rate=24000;channels=1`. mp3 → 400 «Gemini TTS only
  supports response_format=pcm». Чанки нечётной длины встречаются в каждом ответе.
- **Параметры:** `speed` и `instructions` принимаются без ошибки, но
  `supported_parameters` пуст; эффект не подтверждён.
- **Ошибки:**
  - неверный ключ → 401 `{"error":{"message":"User not found.","code":401}}`;
  - неверный голос или пустой `input` → 400 `Provider returned 400`.
- **Цена** (`/api/v1/generation`): $0.5 за 1M входных и $6 за 1M выходных
  токенов, как у Google. Короткое сообщение ≈ $0.00027, ~150 симв. ≈ $0.002.

## 3. Архитектура

```
TTSJob ─▶ _prepare_into ─▶ _generate_gemini_stream_into
                              │  cache hit? ─▶ PcmFramer(raw из кэша) ─▶ кадры
                              │  breaker open? ─▶ "pre_audio" ─▶ Piper
                              ▼
                  GeminiProvider.stream_audio()  (httpx, keep-alive)
                              │ байты PCM 24k моно (любой длины)
                              ▼
                  PcmFramer.feed()  ── soxr.ResampleStream 24k→48k, моно→стерео,
                              │         громкость, нарезка по 3840 байт
                              ▼
                  prepared.channel.put(frames)  ─▶ ContinuousTTSAudioSource (как у MiniMax/Fish)
```

### 3.1 `ttsbot/pcm.py`: свой обработчик PCM (ядро задачи)

Класс `PcmFramer(in_rate: int, in_channels: int = 1, volume_db: float = 0.0)`:

- **`feed(chunk: bytes) -> list[bytes]`** принимает байты любой длины и возвращает готовые кадры по 20 мс для Discord: 48 кГц, стерео, s16le, `PCM_FRAME_BYTES` = 3840 байт. Остатки держит между вызовами:
  - нечётный байт (половина сэмпла);
  - хвост меньше кадра;
  - внутреннее состояние ресэмплера.

  Благодаря этому на стыках чанков нет щелчков.
- **`flush() -> list[bytes]`** отдаёт остаток ресэмплера и дополняет последний кадр тишиной.
- **Передискретизация:** `soxr.ResampleStream(in_rate, 48000, 1, dtype="int16", quality="HQ")`. Потоковая, с малой задержкой, работает с любой входной частотой: если OpenRouter отдаст 24 кГц, 16 кГц или 44.1 кГц, код не меняется. Зависимость `soxr` добавить в `requirements.txt`.
  - Запасной вариант без новой зависимости: FIR-фильтр полуполосы на numpy для ровного ×2. Проще, но работает только при 24 кГц.
- **Моно → стерео** через `np.repeat`. **Громкость:** умножение с насыщением (`np.clip`) до int16.
- **Производительность:** цель < 1 мс на чанк 90 мс. Проверяется тестом-бенчмарком.
- **Pitch** в v1 не делаем: у Gemini нет pitch, а сдвиг через ffmpeg вернул бы задержку. Скорость — только если OpenRouter принимает `speed` (этап 0).

Модуль общий: потом им можно заменить ffmpeg в пути MiniMax, если MiniMax умеет отдавать PCM (проверить отдельно).

### 3.2 `ttsbot/gemini.py`: провайдер

- **`GeminiConfig.from_env()`** читает:
  - `OPENROUTER_API_KEY`;
  - `GEMINI_TTS_MODEL` (по умолчанию `google/gemini-3.8-flash-lite-tts`);
  - `GEMINI_TTS_VOICE` (по умолчанию `Kore`);
  - `OPENROUTER_BASE_URL`;
  - `GEMINI_TTFA_TIMEOUT` (по умолчанию 3.0 с: у OpenRouter лишний переход);
  - необязательные `OPENROUTER_APP_TITLE` и `OPENROUTER_REFERER` — заголовки атрибуции для OpenRouter.

  Метод `cache_key(params)` хеширует модель, голос, громкость, `instructions` и формат.
- **`GeminiProvider`:**
  - **Клиент:** общий `httpx.AsyncClient` с keep-alive, как у Fish. Тёплое соединение экономит ~110 мс.
  - **`stream_audio(text, params) -> AsyncIterator[bytes]`:** `client.stream("POST", "/audio/speech", json={model, input, voice, response_format: "pcm", …})`. Частоту разбирает из `Content-Type` и выставляет её в `self.last_rate`, либо первым элементом отдаёт `AudioFormat`.
  - **`synthesize(text, filename, params)`:** WAV для файлового пути и тестов.
  - **Ошибки:**
    - 401/403 → `GeminiAuthError`;
    - 402 → `GeminiQuotaExhaustedError(QuotaExhaustedError)`: dispatcher уже ставит долгую паузу через `quota_cooldown_seconds`;
    - 429 → `GeminiRateLimitError` с `retry_after`: breaker размыкается на `Retry-After`, а не на полчаса;
    - 5xx и таймаут → обычный отказ.
  - **Пустой ответ** (0 байт аудио, у LLM-TTS такое бывает на «а», «ну») → ошибка до первого звука, дальше Piper.
  - **Счётчики сессии** (`session_requests`, `session_chars`) для `/voicebot stats`.
  - Дедупликацию одинаковых запросов в полёте (`_Flight`, как у Fish) в v1 не делаем.

### 3.3 Реестр голосов: `ttsbot/voice_registry.py`

- **Новый провайдер:** `PROVIDER_GEMINI = "gemini"`, свойство `is_gemini`.
- **Параметры голоса:** `@dataclass(frozen=True) GeminiParams(voice="Kore", model="", volume_db=0.0, instructions="")`. Поле `instructions` — только если этап 0 подтвердит, что оно работает.
- **Хранение:** сериализация в `voices.json` и обратно. Голос без `voice` пропускается с предупреждением, как у Fish без `reference_id`.

### 3.4 Dispatcher: `ttsbot/providers.py`

- **Выбор по умолчанию:** `PrimaryProvider.GEMINI` для `TTS_PRIMARY_PROVIDER=gemini`.
- **Состояние:** в `TTSDispatcher` добавляются поля `gemini` и `gemini_circuit_breaker` (`load_circuit_breaker_from_env()`).
- **Файловый путь:** ветка в `synthesize()` по образцу Fish: кэш → Gemini → при отказе Piper `fallback_profile`.
- **Паузы:** `record_failure()` учит `GeminiRateLimitError` размыкать breaker на `retry_after`.

Это третья копия одного шаблона (MiniMax, Fish, Gemini). Общий интерфейс провайдера — отдельная задача после v1, в эту не смешиваем.

### 3.5 Пайплайн: `ttsbot/pipeline.py`

- **`_should_attempt_stream`:** добавить `is_gemini` при `dispatcher.gemini is not None`.
- **`_prepare_into` и старый `tts_worker`:** ветка Gemini рядом с Fish, через `_prepare_into` / `_play_prepared`. Так оба режима, с предзагрузкой и без, получают стриминг.
- **Новый `_generate_gemini_stream_into(prepared, voice)`:**
  1. **Кэш.** Ключ `gemini:<sha>`, файл `.pcm` с 8-байтным заголовком (частота, каналы). При попадании весь файл пропускается через `PcmFramer` за ~1 мс, без ffmpeg.
  2. **Breaker.** Если разомкнут → `"pre_audio"`.
  3. **Стрим.** Первый чанк ждём до `GEMINI_TTFA_TIMEOUT`. Каждый чанк → `framer.feed()` → `prepared.channel.put(frames)`.
  4. **Ограничения:**
     - `playback_frame_limit` защищает от бесконечного звука;
     - учитывается отмена (`prepared.cancelled`);
     - ошибка посреди потока → `"truncated"`.
  5. **Запись в кэш** атомарно (`.tmp` → commit), только при `"ok"`.
  6. **Лог** `Gemini first frame guild=%s message_to_frame_s=%.3f` для сравнения с Fish по логам.
- **`_voice_speed_factor`:** для Gemini 1.0 (или `speed`, если поддержан).

### 3.6 Команды, статистика и подключение

- **`/voicebot voice-gemini-add name voice [label] [description]`:** автодополнение из 27 голосов. Регистрирует голос и сохраняет реестр.
- **`/voicebot voice-gemini-tune name [volume_db] [instructions]`**, если `instructions` работает.
- **`/voicebot voices`, `/voicebot stats`:** показывают Gemini (запросы и символы за сессию, breaker).
- **`core.py`:** создать провайдер при заданном `OPENROUTER_API_KEY`, закрыть клиент при остановке.
- **`.env.example`:** новые переменные с комментариями.
- **`docker-compose.override.yml`:** ключ можно, как у MiniMax, брать из vault-сайдкара. Сначала достаточно `.env`.

## 4. Тесты

- **`tests/test_pcm.py`:**
  - длина выхода ровно ×2 по сэмплам (с учётом `flush`);
  - все кадры ровно 3840 байт;
  - подача одного и того же сигнала целиком и кусками случайной длины, включая нечётные, даёт одинаковый результат (нет щелчков на стыках);
  - тишина на входе → тишина на выходе;
  - синус 1 кГц сохраняет частоту и амплитуду (±1 дБ);
  - громкость ±6 дБ с насыщением без переполнения;
  - бенчмарк < 1 мс на 90-мс чанк.
- **`tests/test_gemini.py`** (`httpx.MockTransport`):
  - потоковый успех;
  - разбор `Content-Type`;
  - 401 / 402 / 429 с `Retry-After` / 500;
  - таймаут;
  - пустой ответ;
  - счётчики.
- **Реестр:** сериализация туда-обратно, пропуск некорректного голоса.
- **Dispatcher:** маршрутизация по `provider == "gemini"`; разомкнутый breaker → Piper; 402 → долгая пауза, 429 → короткая.
- **Пайплайн** (провайдер замокан):
  - первый кадр уходит до конца потока;
  - обрыв посреди потока → `truncated`;
  - отмена;
  - запись в кэш и попадание в кэш без обращения к API;
  - отказ до первого звука → Piper.
- **Прогон:** весь набор в образе бота, как обычно: `python -m unittest discover -s tests -p 'test_*.py'`.

## 5. Выкатка

1. **Ветка и тесты:** ветка `feat/gemini-openrouter`, тесты в образе, PR.
2. **Деплой инертно:** ни один голос не использует Gemini. Проверить, что старые пути не изменились. Откат на образ `discord-tts-bot:pre-gemini-<дата>`.
3. **Первый голос:** `/voicebot voice-gemini-add gemini-kore Kore`, затем `/voicebot test` на нём.
4. **Замер:** назначить голос тестовому пользователю, собрать ≥ 50 сообщений. Сравнить `message_to_audio_s provider=gemini` с Fish по тем же логам.
5. **Решение:** оставить отдельным голосом или предложить bussshy.
6. **Откат без пересборки:** вернуть пользователю прежний голос или убрать `OPENROUTER_API_KEY`.

## 6. Критерии готовности

- **Задержка:** от сообщения до звука по Gemini p50 ≤ p50 Fish + 0.3 с (сейчас это ≤ ~1.45 с).
- **Качество:** нет щелчков и артефактов на прослушивании и в тесте стыков.
- **Отказы:** 402, 429, 5xx и пустой ответ уходят в Piper без зависаний, с правильной длиной паузы breaker.
- **Затраты:** обработка PCM < 1 мс на чанк, ffmpeg в пути Gemini не запускается.
- **Регрессии:** весь набор тестов зелёный, Fish и MiniMax не затронуты.

## 7. Стоимость (прикидка, уточнить на этапе 0)

- **Длительность:** ~15 600 симв./мес ≈ 16 минут аудио (при ~16 симв./с речи).
- **Токены:** при ~30–40 аудиотокенах в секунду это ~35 000 токенов.
- **Деньги:** по прямой цене Google ($6 за 1M аудиотокенов до конца 2026, $12 с 2027) это ~$0.2–0.4 в месяц. Цену в OpenRouter проверить на странице модели.

## 8. Риски

| Риск | Что делаем |
|---|---|
| OpenRouter не стримит | точка решения на этапе 0; транспорт спрятан за `stream_audio()`, можно уйти напрямую в Gemini API |
| Частота или формат не те, что ожидаем | `PcmFramer` берёт частоту из `Content-Type`, `soxr` работает с любой |
| Чанки нечётной длины | перенос байта в `PcmFramer`, есть тест |
| LLM-TTS странно читает очень короткие фразы или отдаёт пустоту | пустой ответ → Piper; оценить на прослушивании в этапе 0 |
| Кончились кредиты (402) | `QuotaExhaustedError` → долгая пауза breaker, дальше Piper |
| Лишний переход увеличивает TTFA | измерить на этапе 0; keep-alive; `GEMINI_TTFA_TIMEOUT` |
| Третья копия ветки провайдера в dispatcher и пайплайне | осознанно; рефакторинг в общий интерфейс отдельной задачей |

## 9. Объём

~250–350 строк кода (`pcm.py` ~80, `gemini.py` ~150, правки реестра, dispatcher, пайплайна, команд) плюс ~350 строк тестов. Этап 0 — одна короткая сессия; основная часть — одна-две.

## 10. Что реализовано и отличия от плана

- `ttsbot/pcm.py` (`PcmFramer`, `pcm_to_frames`, `apply_gain`, формат кэша),
  `ttsbot/gemini.py` (`GeminiProvider.open_stream` / `fetch_pcm` / `synthesize`),
  ветки в реестре, dispatcher, пайплайне, `core.py`, `/voicebot stats` и `voices`.
- **Ресэмплинг в float32**, а не int16: soxr дизерит целочисленный выход,
  тишина превращалась в шум ±1, а результат зависел от разбиения на чанки.
- **Бюджет первого звука растёт с длиной текста:**
  `GEMINI_TTFA_TIMEOUT` (3 с) + `GEMINI_TTFA_PER_CHAR` (0.03 с) × символы.
  Фиксированные 3 с отрезали бы всё длиннее ~100 символов, потому что
  OpenRouter отдаёт звук только после полной генерации.
- **Команды:** в группе `/voicebot` уже 25 подкоманд (лимит Discord), поэтому
  отдельной `voice-gemini-add` нет: голос добавляется через
  `/voicebot voice-add name voice_id:Kore provider:Gemini` (автодополнение
  голосов, пробный платный запрос перед сохранением). `voice-gemini-tune` и
  `instructions` не сделаны: эффект `instructions` не подтверждён;
  `volume_db` правится в `voices.json`.
- **Кэш** хранит сырой PCM (`.pcm`, 12-байтный заголовок `RPCM`, частота,
  каналы, разрядность) до применения громкости, поэтому смена громкости
  не сбрасывает кэш. Piper-фоллбэк для Gemini-голоса в кэш не пишется.
- **429 с `Retry-After`** размыкает breaker ровно на это время (общая логика
  `TTSDispatcher.record_failure` для любого исключения с `retry_after`).
